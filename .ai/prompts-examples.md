# 角色交接提示词

用户在会话间切换，每轮按 AGENTS.md 先读 brief、plan 概览和本轮任务、index 相关入口，再按角色补读材料，完成范围后同步并停止。默认规划／审查用 Astra、执行用 Sol；按实际安排调整。

## 场景 A：嵌入式 DMA 修改

规划会话：

```text
本轮只做规划。按共同入口定位 ETH DMA RX 模块，读取相关调用链、DMA 描述符所有权、cache invalidate 说明和并发证据。在 .ai/plan.md 用短条目写清输入来源、实际前置依赖、最小修改、输出位置、模块边界、验收角色与条件及下一动作，更新有效决策和索引，同步后停止。
```

## 场景 B：声学定位算法改进

### 阶段 1：Astra 规划与路线选择

```text
先读共同入口，再查看声学定位相关决策、模块和实测结果。围绕目标推荐一条路线，在 .ai/plan.md 记录简短概览及任务输入、依赖、输出、模块边界、实施步骤、验收角色与条件和下一动作。保留核心路线，精简失效记录，索引注明相关材料何时读取。完成后同步并停止。
```

### 阶段 2：Sol 实施与检查

```text
先读共同入口、本轮任务的输入及相关审查项，再按 .ai/plan.md 实施授权范围。确认入口、数据流和依赖方向，相关模块的职责拆分随修改完成。使用 ./scripts/check.sh 验证，按实际结果更新任务和概览；输入、接口或结论变化时标记受影响的后续任务需要复核。范围外发现记到 backlog；同根因三次失败后记录阻塞。同步后停止，交由用户安排独立审查。
```

### 阶段 3：Astra 独立审查

```text
先读共同入口和本轮相关审查、决策，对照目标与任务输入审查实际 diff、原始证据和受影响调用链，核对验收结果及下游影响。把有证据的 P0/P1/P2 问题、影响和修复要求写入 .ai/review.md，并在 plan 对应任务记录审查状态。必要时从 ./scripts/check.sh 复验。同步后停止，不在审查轮修改产品代码。
```

## 场景 C：接入图片 / 视频生成 Agent

```text
登记实际生成 agent、能力和文件访问。把用途、输出位置、规格与内容接受条件写入计划，准备完整自包含 prompt。文件型 agent 接收产物后将图片／视频放 assets/generated/，完整 prompt 放旁边，在 .ai/asset-manifest.md 留入口和接受状态，并更新 .ai/index.md。机械检查从 ./scripts/check.sh 进入，内容由用户或指定审查者判断。
```

## 场景 D：Workbuddy 阅读与汇报

```text
按 AGENTS.md 读取共同入口，再通过 .ai/index.md 查看本轮主题的采用结果与支持证据；排障时再补读相关过程日志。总结项目目标、方法、进展和下一步，使用 references/writing-rules.md。报告、问答及附件放 out/workbuddy/<topic>/，沿用索引中已有的目录约定。记录来源与采用状态，更新 .ai/index.md。无文件访问时由文件型 agent 提供本轮上下文、接收完整内容及建议文件名并落盘。
```

## 场景 E：已有项目更新规则

```text
用最新 $jiaojie 更新当前项目。按 references/update-rules.md 合并 AGENTS.md、同步与写作规则、名册及内容索引，采用共同入口加按任务读取，在现有 plan 中整理概览和真实任务依赖。保留核心路线、项目专属要求、用户改动和现有安全检查。完成后运行统一检查并报告实际结果。
```
