# 角色交接提示词

用户在会话间切换，每轮按 AGENTS.md 顺序读取当前文档，完成范围后同步并停止。默认规划／审查用 Astra、执行用 Sol；按实际安排调整。

## 场景 A：嵌入式 DMA 修改

规划会话：

```text
本轮只做规划。理解 ETH DMA RX 接收路径，梳理调用链、DMA 描述符所有权、cache invalidate 位置和已知并发风险。把最小修改、模块边界与验收条件写入 .ai/plan.md，更新有效决策和索引，同步后停止。
```

## 场景 B：声学定位算法改进

### 阶段 1：Astra 规划与路线选择

```text
读取当前交接、索引及相关代码和实测结果。围绕声学定位目标推荐一条路线，说明证据、模块边界、实施步骤和验收条件，写入 .ai/plan.md。保留核心路线，精简失效记录，更新相关索引。完成后同步并停止。
```

### 阶段 2：Sol 实施与检查

```text
按 .ai/plan.md 实施本轮范围。先确认入口、数据流和依赖方向，相关模块的职责拆分随修改完成。使用 ./scripts/check.sh 验证，按实际结果更新计划、决策和索引。范围外发现记到 backlog；同根因三次失败后记录阻塞。同步后停止，交由用户安排独立审查。
```

### 阶段 3：Astra 独立审查

```text
对照目标和计划审查实际 diff，核对检查结果及受影响调用链。把有证据的 P0/P1/P2 问题、影响和修复要求写入 .ai/review.md。必要时从 ./scripts/check.sh 复验。同步后停止，不在审查轮修改产品代码。
```

## 场景 C：接入图片 / 视频生成 Agent

```text
登记实际生成 agent、能力和文件访问。把用途、输出位置、规格与内容接受条件写入计划，准备完整自包含 prompt。文件型 agent 接收产物后将图片／视频放 assets/generated/，完整 prompt 放旁边，在 .ai/asset-manifest.md 留入口和接受状态，并更新 .ai/index.md。机械检查从 ./scripts/check.sh 进入，内容由用户或指定审查者判断。
```

## 场景 D：Workbuddy 阅读与汇报

```text
读取 AGENTS.md、当前交接和 .ai/index.md，根据任务查看来源。总结项目目标、方法、进展和下一步，使用 references/writing-rules.md。报告、问答及附件放 out/workbuddy/<topic>/，沿用索引中已有的目录约定。记录来源与采用状态，更新 .ai/index.md。无文件访问时把完整内容及建议文件名交给文件型 agent 落盘。
```

## 场景 E：已有项目更新规则

```text
用最新 $jiaojie 更新当前项目。按 references/update-rules.md 将规则合并到 AGENTS.md、同步与写作规则、名册及内容索引，精简 .ai。保留核心路线、项目专属要求、用户改动和现有安全检查。完成后运行统一检查并报告实际结果。
```
