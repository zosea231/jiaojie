# Jiaojie 协作规则的理由

## 可读性与模块化

新会话先需要定位入口，再需要理解当前目标和依赖关系。稳定命名、单一职责、明确的数据流和内容索引减少反复探索。拆分职责混杂文件和消除循环依赖应随相关开发完成；规模由实际问题决定。

## 当前文档与核心路线

`.ai/` 保存当前目标、路线、计划、审查、有效决策和必要证据入口。过期记录长期与当前指令并存，会使下一会话恢复旧路线。按 `sync-rules.md` 在对应条目更新状态，删去失效待办和重复历史；详细实验、生成提示词和采用稿留在原目录。

共同入口是 AGENTS.md、brief、plan 概览与本轮任务，以及 index 相关条目。先确认目标和阶段，再按角色读取相关审查、决策、模块说明及原始证据。全局约束和阻塞问题留在共同入口，详细理由保留链接；入口不足时逐步补读。这样可以减少每个角色反复读取无关资料，实际缓存效果取决于运行环境和输入组织。

`.ai/index.md` 是跨 agent 的内容导航，注明资料适用于什么任务、何时读取，链接到模块入口、相关章节、报告和资产记录。移动文件或形成采用稿时同步索引。详细模块上下文沿用已有目录，索引不重复任务进度。

## 任务依赖与变更影响

项目可以采用 small 或 large 两种模式，根 AGENTS、brief／plan／index 入口保持一致。small 在现有 plan 内组织任务，large 用工作流局部 brief／plan 保存详细上下文，根计划只维护结果和真实依赖。按实际读取负担升级，先拆文档、保留代码与数据路径；具体构建见 [project-architecture.md](project-architecture.md)。

plan 保留简短概览和按真实工作划分的任务小节。每个任务说明输入来源、存在的前置条件、输出位置、执行／验收角色、验收依据与下一动作；小任务保持一个短条目。依赖直接链接任务名或来源，不需要另一套状态文件或调度系统。

大型模式的依赖导航采用图式组织：工作流与资产为节点，真实输入输出为边，链接能按需展开详情。复杂关系才画图；使用现有 Markdown 与 Git，不要求图数据库或自动调度。稳定入口、局部更新和少量共同状态有助于减少重复输入，缓存效果由运行环境决定。

上游数据、接口或结论改变时，依赖关系帮助定位需要复核的下游结果，并记录原因。索引或文案整理本身不要求重新验收已有结果。原证据保留，工程检查仍走统一入口，执行范围仍由用户指定。

## 人工切换与角色边界

默认由用户在两个 Codex 会话间切换：Astra 规划／独立审查，Sol 实施／修复。角色可按任务安排，模型名称不构成运行依赖。实现者验证自身改动，独立审查由另一个指定会话承担。名册记录参与者及文件访问能力，交接不建立锁或调度机制。

Claude Code 参与时使用引用 AGENTS.md 的薄入口，减少共享规则副本。Workbuddy 负责阅读、问答与汇报，按主题读取采用结果和支持证据，过程日志按问题补充；没有文件访问时，由文件型 agent 提供本轮上下文并落盘。

用户安排并行时，以独立分支和 worktree 隔离需要隔离的改动。文档仍随分支保存，通过分支提交读取其他任务最新状态，合并时同步全局概览；不把主分支文档当作实时共享文件。大数据和环境通过索引显式引用。

## 验证与安全措施

`./scripts/check.sh` 保持唯一验证入口，以便所有会话使用同一套工程检查。必要的新验收放 `scripts/checks/<name>.sh`；检查已覆盖时直接复用。模板提供常见技术栈示例，首次使用按项目工具链调整。

普通测试验证行为。防止未知假想事故的额外 hash、contract 冻结、baseline 和 gate 默认不加，只有说明具体失败场景及 Git、版本号、主键、事务、唯一约束、类型和普通测试为何不足时才能加。既有认证、数据安全、不可逆操作和发布措施全部保留。文档同步和措辞使用阅读判断，无需验证脚本。

同根因连续三次检查失败后停止修改与重跑，记录阻塞证据和所需决策；只有检查推进或识别不同根因才重置。

## 直接写作

`writing-rules.md` 将 Anti-Defensive Writing 用于文档、汇报和日常交接。它要求清楚陈述结果、保留必要限定和不利证据，避免反复免责将可选改进变成强制任务。最终标题、文件名和交付说明围绕最终采用状态，读者无需知道会话中的措辞纠正。

## 嵌入式约束

适用时注意 ISR、DMA 所有权、缓存一致性、对齐与 volatile。底层驱动的动态分配须有明确授权，公共协议行为变化说明理由。项目更新时保留已采用的专属约束。
