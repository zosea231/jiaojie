# 交接文档同步与精简规则

开发过程中随事实变化更新相关状态、模块入口和内容索引。用户要求同步时立即完成同步；阶段结束时集中核对，说明状态后停止，由用户选择下一角色。

## 写入位置

| 内容 | 位置 |
|---|---|
| 核心目标、当前路线与范围 | `.ai/brief.md` |
| 简短概览；任务输入、依赖、输出、角色、进度、验收与下一动作 | `.ai/plan.md` |
| 仍有效的 P0/P1/P2 发现及复核状态 | `.ai/review.md` |
| 本次不处理的有效事项 | `.ai/backlog.md` |
| 影响后续工作的决策与原因 | `.ai/decision-log.md` |
| 实际参与者、角色和文件访问能力 | `.ai/roster.md` |
| 模块、资料、产物、证据的读取时机与存放入口 | `.ai/index.md` |
| 生成资产、完整提示词入口、检查与接受状态 | `.ai/asset-manifest.md` |

large 模式的根 brief／plan／index 是全局入口。任务目标、边界、输入／输出在 `.ai/workflows/<workflow>/brief.md`，详细步骤、进度、验收与下一动作在局部 plan；根 plan 每个 workflow 仅一条简要结果与下一步／依赖。其他记录按影响范围在根或局部按需创建，index 链接到其唯一正文，根不复制局部详情。目录与 worktree 规则见 `project-architecture.md`（大型模式随初始化复制）。

## 精简方式

1. 保持核心目标、路线与章节结构稳定，直接修改对应条目。plan 顶部保留简短概览和稳定任务入口；全局约束或影响所有任务的问题在共同入口留简述与链接。不要每轮在顶部追加整段历史。
2. 删除已失效、已解决且无需继续跟踪、或明显偏离路线的活跃记录；合并仍适用的决策理由。backlog 和 decision-log 持续整理，不永久只追加。
3. 有用实测结果、负结果、来源和必要限制保留一次；详细参数、日志、提示词、旧方案留在原 `references/`、`out/` 或产物目录，交接只保留入口。
4. 不因文档瘦身删除代码、数据、论文、用户采用稿、必要审计／迁移记录或仍影响判断的证据，不自行关闭未复核审查项。
5. 充分利用已有 Git 历史。无版本控制且需大幅整理时，可将必要原稿保留到 `out/`，无需每轮快照、哈希或新的历史维护机制。
6. 新增、移动、采用或停用产物时更新索引。沿用有效目录和命名；Workbuddy 的文稿及附件遵守 `.ai/index.md` 的存放约定。
7. 架构整理后同步受影响模块的职责、入口和依赖方向，替换失效路径。索引链接到详细资料，不复制其正文。

## 任务上下文与依赖维护

- 本轮任务在 plan 中记录目标／范围、输入来源、真实前置依赖、输出位置、执行／验收角色、验收依据、状态和下一动作。小任务用短条目，多任务用稳定小节名互相链接。
- 详细代码说明、实验条件和过程材料沿用模块 README、references 或产物目录；index 注明适用任务和何时读取。任务状态在 plan 与原记录维护，索引负责导航。
- 完成、阻塞或交付时，更新本轮任务、概览和受影响的入口。尚需独立审查的产物如实标为待审查，后续接收者由用户安排。
- 上游输入、接口或结论实际变化时，沿依赖定位受影响的后续任务，注明哪些结果需要复核及原因，并保留原证据。仅索引整理或文案更新不触发无关复核；影响分析不替代统一检查，也不扩大本轮授权范围。
- Workbuddy 汇报交接提供当前目标、阶段、采用结果和来源入口；排障材料按具体问题补充。无文件访问时，提供足以完成本轮角色的自包含上下文。

large 模式在可交付步骤结束、阻塞或跨任务输入变化时更新局部状态并简要同步根 plan；普通推进只改对应局部计划，不每次调用都写全局文档。稳定输入和正文保持原位，避免频繁改名、全量重排和重复日志。

## 多分支交接（按需）

worktree 是完整 checkout，文档随分支提交。写共享文件前重读并保留其他任务条目；提交当前 workflow 的实现、文档与证据入口，推送依用户授权。其他分支的最新已提交计划用 `git show <branch>:.ai/workflows/<workflow>/plan.md` 查看；跨机器先 fetch，再读 `origin/<branch>`。未提交工作需在对应 checkout 读取，主分支概览只反映已合并状态。合并时核对真实进度并同步概览，用普通 Git 处理冲突。

## 表达与检查

先读 `references/writing-rules.md`；起草正文时读其内置写作技能。交接围绕当前目标、结果、证据和下一步，面向完全没看过会话的读者。最终采用状态的包装要求见 AGENTS.md。

改动完成后从 `scripts/check.sh` 验证。缺少必要行为验收时新增 `scripts/checks/<name>.sh` 并记录理由，保留既有检查；单纯文档语义通过阅读核对，不新增同步门禁或措辞测试。遵守同根因三次失败停止规则，收尾如实说明实际检查结果。
