# 将最新 Jiaojie 规则应用到已有项目

用户要求更新 Jiaojie 项目规则时，完成规则合并、索引更新和检查。最新用户指令及项目既有授权继续有效，常规文档合并直接执行。

1. 先读项目 AGENTS.md、`.ai/brief.md`、plan 概览与本轮任务、index 相关入口，再按本次规则更新范围补读同步／写作规则、检查入口、相关决策和现有目录。确认核心路线、全局约束、采用稿、用户修改与安全措施；项目规则仍要求全量读取时先遵守现行要求。
2. 依据实际工作流选择 small 或 large，并在 brief 或 index 写明。small 运行 `scripts/init_workflow.sh <project>`；large 运行 `scripts/init_workflow.sh <project> --mode large --workflow <name> ...`。只有 Claude Code 实际参与时才加 `--with-claude`。脚本跳过已有文件，后续合并由当前 agent 完成。
3. 将最新 `assets/AGENTS.md` 的可读性／模块化原则、按任务读取、任务依赖、文档精简、索引与产物位置、防御性编程阈值、写作和最终包装条款合并到项目 AGENTS.md。保留项目专属要求、实际角色安排、已有安全措施和检查。将旧的每轮全量必读规则替换为共同入口加相关材料，保留确有用途的项目专属必读项；统一相关提示词和参与者入口。删去冲突的通用旧指令，例如 backlog 永久只追加、默认必须维护 Claude 副本、要求绕过项目既有哈希检查的绝对禁令。
4. 合并 `references/sync-rules.md` 和 `references/writing-rules.md`，复制缺失的内置写作技能与许可；已有写作偏好继续有效。更新内置原文时保留用户扩展到 writing-rules.md，保留上游归属与许可。同步目录及阅读入口。
5. 根据真实文件填充 `.ai/index.md`，索引已有模块、资料与采用稿，注明适用任务和何时读取，尽量链接到相关章节；任务状态仍由 plan 和原记录维护。沿用现有输出目录。名册只登记实际使用者，Workbuddy 启用时注明文件访问和产物目录。Claude Code 未参与时保留现有 CLAUDE.md，不要求持续维护；参与时将必要专属内容保留，并引用共享 AGENTS.md。
6. 将 plan 的路线、阶段、当前任务、全局约束／阻塞审查入口和下一动作整理为简短概览。small 用现有任务小节补充真实输入、前置依赖、输出位置、执行／验收角色及证据；小任务保持短条目，只链接实际依赖。large 将详细目标、边界、计划和验收整理到对应 workflow 的 brief／plan，根 plan 仅保留结果、下一步和依赖；删除重复正文后保留原证据与有效决策入口，index 补齐局部文档、代码和分支导航。large 构建及 small 渐进升级按 [project-architecture.md](project-architecture.md)；只补模板不等于完成升级。实际输入或结论变化时才标记受影响的后续工作需要复核。保留核心目标、有效理由和未完成验收，不用空模板覆盖当前状态。
7. 从项目 `scripts/check.sh` 运行既有检查，报告实际结果。只为缺失的行为验收加普通测试，不为规则更新增加哈希、baseline、contract 或 gate。

更新后再次运行初始化只补缺失文件。再次请求规则更新时比较实际内容，已有一致规则直接保留，不重复添加章节或改动有效路线。

升级 large 时补齐 worktree 按分支读取的规则、实际数据／服务器位置索引，以及根 `.gitignore` 中的 `/worktrees/`。初始化保留已有 `.gitignore`，合并由 agent 完成。源码、数据、产物、环境、Git 历史和运行中部署沿用原位；目录迁移另列映射与验证范围。文档升级在各任务交接节点切换入口，通常不要求所有 loop 停止。不要因规则更新自动提交、发布或恢复运行作业。
