# 将最新 Jiaojie 规则应用到已有项目

用户要求更新 Jiaojie 项目规则时，完成规则合并、索引更新和检查。最新用户指令及项目既有授权继续有效，常规文档合并直接执行。

1. 按 SKILL.md 的顺序读取项目当前 `.ai/`，然后读 AGENTS.md、现有同步／写作规则、检查入口和内容目录。确认核心路线、采用稿、用户修改与安全措施。
2. 运行 `scripts/init_workflow.sh <project>` 补齐缺失文件。只有 Claude Code 实际参与时才加 `--with-claude`。脚本跳过已有文件，后续合并由当前 agent 完成。
3. 将最新 `assets/AGENTS.md` 的可读性／模块化原则、文档精简、索引与产物位置、防御性编程阈值、写作和最终包装条款合并到项目 AGENTS.md。保留项目专属要求、实际角色安排、已有安全措施和检查。删去冲突的通用旧指令，例如 backlog 永久只追加、默认必须维护 Claude 副本、要求绕过项目既有哈希检查的绝对禁令。
4. 合并 `references/sync-rules.md` 和 `references/writing-rules.md`，复制缺失的内置写作技能与许可；已有写作偏好继续有效。更新内置原文时保留用户扩展到 writing-rules.md，保留上游归属与许可。同步目录及阅读入口。
5. 根据真实文件填充 `.ai/index.md`，索引已有模块、资料与采用稿；沿用项目现有输出目录。名册只登记实际使用者，Workbuddy 启用时注明文件访问和产物目录。Claude Code 未参与时保留现有 CLAUDE.md，不要求持续维护；参与时将必要专属内容保留，并引用共享 AGENTS.md。
6. 按精简规则整理受影响 `.ai/` 条目；保留核心目标、路线、当前阶段、有效理由、未完成验收与证据入口。不要用空模板覆盖当前状态，也不要借更新规则启动产品重构。
7. 从项目 `scripts/check.sh` 运行既有检查，报告实际结果。只为缺失的行为验收加普通测试，不为规则更新增加哈希、baseline、contract 或 gate。

更新后再次运行初始化只补缺失文件。再次请求规则更新时比较实际内容，已有一致规则直接保留，不重复添加章节或改动有效路线。
