# 交接文档同步与精简规则

开发过程中随事实变化更新相关状态、模块入口和内容索引。用户要求同步时立即完成同步；阶段结束时集中核对，说明状态后停止，由用户选择下一角色。

## 写入位置

| 内容 | 位置 |
|---|---|
| 核心目标、当前路线与范围 | `.ai/brief.md` |
| 阶段计划、进度、验收条件与下一动作 | `.ai/plan.md` |
| 仍有效的 P0/P1/P2 发现及复核状态 | `.ai/review.md` |
| 本次不处理的有效事项 | `.ai/backlog.md` |
| 影响后续工作的决策与原因 | `.ai/decision-log.md` |
| 实际参与者、角色和文件访问能力 | `.ai/roster.md` |
| 模块、资料、产物、证据与存放约定 | `.ai/index.md` |
| 生成资产、完整提示词入口、检查与接受状态 | `.ai/asset-manifest.md` |

## 精简方式

1. 保持核心目标、路线与章节结构稳定，直接修改对应条目。不要每轮在顶部追加整段历史。
2. 删除已失效、已解决且无需继续跟踪、或明显偏离路线的活跃记录；合并仍适用的决策理由。backlog 和 decision-log 持续整理，不永久只追加。
3. 有用实测结果、负结果、来源和必要限制保留一次；详细参数、日志、提示词、旧方案留在原 `references/`、`out/` 或产物目录，交接只保留入口。
4. 不因文档瘦身删除代码、数据、论文、用户采用稿、必要审计／迁移记录或仍影响判断的证据，不自行关闭未复核审查项。
5. 充分利用已有 Git 历史。无版本控制且需大幅整理时，可将必要原稿保留到 `out/`，无需每轮快照、哈希或新的历史维护机制。
6. 新增、移动、采用或停用产物时更新索引。沿用有效目录和命名；Workbuddy 的文稿及附件遵守 `.ai/index.md` 的存放约定。
7. 架构整理后同步受影响模块的职责、入口和依赖方向，替换失效路径。索引链接到详细资料，不复制其正文。

## 表达与检查

先读 `references/writing-rules.md`；起草正文时读其内置写作技能。交接围绕当前目标、结果、证据和下一步，面向完全没看过会话的读者。最终采用状态的包装要求见 AGENTS.md。

改动完成后从 `scripts/check.sh` 验证。缺少必要行为验收时新增 `scripts/checks/<name>.sh` 并记录理由，保留既有检查；单纯文档语义通过阅读核对，不新增同步门禁或措辞测试。遵守同根因三次失败停止规则，收尾如实说明实际检查结果。
